# 22. 도구 고르기: 나와 맞는 AI 코딩 도구

AI 코딩 도구는 종류가 많다. 이름을 들어본 것만 해도 Claude Code, Cursor, v0, Lovable, Replit 등이 있다. 다 좋아 보이지만, 사실 도구는 '어떤 방식으로 일하느냐'에 따라 3가지 유형으로 나뉜다. 유형을 이해하면 선택이 쉬워진다. 이 장에서는 3가지 유형을 비개발자 관점에서 정리하고, 요금제를 비교한 뒤, 처음 시작할 때의 조합을 제안한다.

## 도구 유형 3가지

### 유형 1: 채팅·CLI 에이전트형 — Claude Code

Claude Code는 대화하듯이 일을 시키는 도구다. 터미널(검은 화면에 글자를 치는 프로그램)에서 실행되며, "메뉴판 화면 만들어줘"라고 말하면 프로젝트 폴더 안의 파일을 직접 만들고 고친다. 채팅으로 지시하고, AI가 실제 파일을 건드리는 방식이다.

특징은 다음과 같다. 내 컴퓨터의 파일에 직접 접근하므로 큰 프로젝트도 다룰 수 있다. 명세서 파일을 폴더에 넣어두고 "명세서대로 만들어줘"라고 하면 그대로 따라간다. 여러 파일을 한 번에 고치는 것도 잘한다.

장점은 강력한 만큼 자유도가 높다는 것이다. 단점은 터미널이라는 낯선 화면을 써야 한다는 것이다. 명령어를 외울 필요는 없지만(대화하듯이 쓰면 된다), 처음 보는 화면이라 진입 장벽이 있다. 컴퓨터에 설치 과정도 필요하다.

추천 대상: 명세서를 파일로 관리하면서 차근차근 만들고 싶은 사람. 이 책의 20~21장 방식으로 명세서를 준비했다면 잘 맞는다.

### 유형 2: 에디터 내장형 — Cursor

Cursor는 코드 편집 프로그램(에디터) 안에 AI가 들어간 형태다. 화면 왼쪽에 파일을 보고, 오른쪽(또는 옆 패널)에 AI와 대화하면서 고친다. 코드를 직접 보는 화면이라 "이 부분이 어떻게 생겼는지" 눈으로 확인하기 쉽다.

특징은 다음과 같다. 파일 목록이 눈앞에 보이므로 AI가 뭘 만들었는지 바로 확인할 수 있다. 특정 부분을 드래그해서 "여기만 고쳐줘"라고 지정하기 쉽다. 코드를 몰라도 파일 구조가 눈에 들어온다.

장점은 시각적으로 확인하면서 작업할 수 있다는 것이다. 단점은 결국 코드가 화면에 보인다는 것이다. 코드를 읽을 필요는 없지만, 파일이 잔뜩 보이는 화면에 익숙해져야 한다.

추천 대상: 결과물을 눈으로 확인하면서 조금씩 고쳐나가고 싶은 사람. 디자인 수정을 자주 할 것 같으면 편하다.

### 유형 3: 브라우저에서 바로 만드는 빌더형 — v0, Lovable, Replit

빌더형은 웹사이트에 접속해서 바로 만드는 도구다. 설치가 필요 없고, 브라우저에서 설명을 쓰면 미리보기 화면이 바로 뜬다. v0는 화면 디자인 만들기에 강하고, Lovable은 앱 전체를 빠르게 만들 때 많이 쓰이고, Replit은 만들고 바로 인터넷에 공개하기까지 한 번에 된다.

특징은 다음과 같다. 가입하고 바로 시작할 수 있다. "카페 메뉴판 사이트 만들어줘"라고 쓰면 몇 분 안에 화면이 나온다. 미리보기가 바로 되므로 20장의 명세서를 붙여넣고 결과를 확인하는 흐름이 빠르다.

장점은 시작이 가장 쉽다는 것이다. 단점은 내 컴퓨터의 파일이 아니라 서비스 안에 결과물이 있다는 것이다. 나중에 파일을 빼내거나 다른 도구로 옮기려면 별도 작업이 필요하다. 복잡한 기능이 들어가면 한계가 빨리 온다.

추천 대상: "일단 돌아가는 것을 빨리 보고 싶다"는 사람. 아이디어 검증용으로 만들 때 가장 빠르다.

## 도구별 자세히 보기

### Claude Code: 대화로 파일까지 만지는 방식

Claude Code를 쓰면 이런 흐름이 된다. 컴퓨터에 프로젝트 폴더를 만들고, 명세서 파일을 넣어둔다. 터미널에서 Claude Code를 실행한 뒤 "명세서 파일을 읽고 1단계(메뉴판 화면)부터 만들어줘"라고 말한다. AI가 파일을 만들고, 다 되면 "완료됐습니다. 확인해 보세요"라고 말한다. 미리보기로 확인하고 "2단계 해줘"라고 이어간다.

이런 사람에게 맞다. 명세서를 미리 써둔 사람, 단계별로 차근차근 진행하고 싶은 사람, 나중에 파일을 직접 보관하고 싶은 사람. 20~21장의 명세서 방식과 궁합이 가장 좋다.

이런 사람에게는 맞지 않는다. 터미널이라는 검은 화면이 부담스러운 사람, 설치 과정을 혼자 하기 어려운 사람. 이 경우에는 빌더형으로 먼저 시작해서 감을 잡은 뒤 넘어오는 게 낫다.

요금 관련 메모: 무료 플랜이 없으므로 시작부터 결제가 필요하다. 다만 Pro(월 20달러) 하나로 시작하면 충분하다. Max는 작업량이 많은 팀이나 하루 종일 쓰는 사람용이다.

### Cursor: 눈으로 보면서 고치는 방식

Cursor를 쓰면 이런 흐름이 된다. 프로그램을 열고 프로젝트 폴더를 연다. 왼쪽에 파일 목록, 가운데에 미리보기(또는 코드), 옆에 AI 대화창이 있다. "메뉴판 화면 만들어줘"라고 하면 파일이 생기고, 특정 버튼을 드래그해서 "이 버튼을 더 크게 해줘"라고 하면 그 부분만 고친다.

이런 사람에게 맞다. 결과물을 눈으로 확인하면서 고치고 싶은 사람, 디자인 수정을 자주 할 것 같은 사람. "말로 설명하기보다 가리키면서 말하고 싶다"는 사람에게 편하다.

이런 사람에게는 맞지 않는다. 화면에 코드가 보이는 것 자체가 부담스러운 사람. 코드를 읽을 필요는 없지만 파일이 많이 보이면 위축되는 사람은 빌더형이 낫다.

요금 관련 메모: Hobby 무료 플랜으로 시작할 수 있다. 사용량 제한에 걸리면 그때 Pro(월 20달러)를 고려한다. 무료로 어디까지 되는지 직접 써보는 게 가장 빠르다.

### Lovable: 브라우저에서 앱을 바로 만드는 방식

Lovable을 쓰면 이런 흐름이 된다. 사이트에 가입하고 입력창에 "카페 픽업 주문 앱 만들어줘"와 명세서를 붙여넣는다. 몇 분 뒤 미리보기 화면이 나온다. "버튼을 더 크게 해줘"라고 채팅으로 말하면 바로 반영된다.

이런 사람에게 맞다. 설치 없이 지금 바로 만들고 싶은 사람, 아이디어가 될지 안 될지 빨리 보고 싶은 사람. 명세서를 붙여넣으면 첫 결과물이 빨리 나온다.

이런 사람에게는 맞지 않는다. 파일을 내 컴퓨터에 두고 싶은 사람, 복잡한 기능을 넣고 싶은 사람. 프로젝트가 커지면 다른 도구로 옮겨야 할 수 있다.

요금 관련 메모: 무료로 하루 5크레딧이 주어진다. 크레딧은 요청할 때마다 차감되므로, 고치기를 반복하면 하루치가 빨리 닳는다. Pro(월 25달러)는 본격적으로 쓸 때 고려한다.

### v0: 화면 디자인 만들기에 강한 방식

v0를 쓰면 이런 흐름이 된다. "카페 메뉴판 화면"처럼 화면 위주로 설명하면 디자인이 잘 나온 화면이 나온다. 여러 시안을 만들어 비교하기도 쉽다.

이런 사람에게 맞다. 화면 디자인이 가장 중요한 사람, 여러 디자인을 비교해보고 싶은 사람. "기능보다 보이는 게 먼저"인 프로젝트에 잘 맞는다.

요금 관련 메모: 무료로 소액 크레딧이 주어진다. Plus(월 30달러/사용자)는 팀으로 쓸 때의 요금제다. 혼자 쓴다면 무료 범위에서 감을 잡고 결정한다.

### Replit: 만들고 바로 공개까지 되는 방식

Replit을 쓰면 이런 흐름이 된다. 브라우저에서 만들고, "Deploy"(배포) 버튼을 누르면 인터넷 주소가 생긴다. 그 주소를 손님이나 지인에게 바로 보여줄 수 있다.

이런 사람에게 맞다. 만든 것을 빨리 공개하고 싶은 사람, "내 가게 홈페이지 주소를 당장 갖고 싶다"는 사람. 배포 과정이 따로 없어서 편하다.

요금 관련 메모: 무료로 시작할 수 있고, Core(월 20달러)는 더 많이 쓸 때 고려한다.

## 도구 선택 시 자주 묻는 질문

### 한국어로 말해도 되나요?

된다. 이 장의 5개 도구 모두 한국어로 지시하면 한국어로 답하고 결과물을 만든다. 명세서도 한국어로 쓰면 된다. 오류 메시지는 영어로 뜨는 경우가 있지만, 31장에서 다루듯이 그대로 복사해서 AI에게 주면 된다.

### 결제는 어떻게 하나요?

대부분 해외 카드 결제를 받는다. 국내 체크카드·신용카드 중 해외 결제가 되는 카드면 된다. 결제 전에 무료 범위를 먼저 써보고, 정말 계속 쓸 것 같을 때만 결제한다.

### 설치가 필요한 도구는 어떻게 설치하나요?

Claude Code와 Cursor는 설치가 필요하다. 각 공식 사이트의 안내를 따라 하면 된다. 설치가 막히면 AI에게(또는 챗봇에게) "Claude Code 설치가 안 돼요. 이 화면이 나와요"라며 화면 내용을 그대로 보여주고 물어보면 된다. 31장의 증상 설명 4요소가 여기서도 통한다.

### 도구를 중간에 바꿔도 되나요?

된다. 빌더형에서 만든 결과물은 파일로 내려받을 수 있다(각 서비스의 내보내기 기능). 내려받은 폴더를 Claude Code나 Cursor에서 열면 이어서 작업할 수 있다. 명세서 파일만 잘 보관해 두면(21장), 도구 이동이 쉬워진다.

## 요금제 요약표

아래 수치는 2026년 10월 기준 조사값이며 바뀔 수 있다. 결제 전 반드시 공식 페이지에서 확인하자.

| 도구 | 무료 | 유료 |
|------|------|------|
| Claude Code | 무료 플랜 없음 | Claude Pro 월 20달러부터(연간 결제 시 월 17달러 상당), Max 월 100달러/200달러 |
| Cursor | Hobby 무료(사용량 제한) | Pro 월 20달러, Pro+ 월 60달러, Ultra 월 200달러, Teams 월 40달러/사용자 |
| Lovable | 무료 일 5크레딧 | Pro 월 25달러 |
| v0 | 무료 소액 크레딧 | Plus 월 30달러/사용자 |
| Replit | 무료(사용량 제한) | Core 월 20달러 |

요금제를 볼 때 주의할 점이 있다. '크레딧' 방식(Lovable, v0)은 AI를 쓸 때마다 크레딧이 차감된다. 많이 고치면 빨리 닳는다. '구독' 방식(Claude Code의 Pro, Cursor의 Pro)은 월정액으로 일정량을 쓴다. 처음에는 무료 범위 안에서 얼마나 쓸 수 있는지 직접 써보는 게 가장 정확하다.

환율을 대략 1,400원으로 잡으면 월 20달러는 약 2만 8천원이다. 커피 몇 잔 값이라 생각하면 부담이 크지 않지만, "써보지도 않고 결제"는 피하는 게 좋다. 모든 도구가 무료 범위나 체험 구간을 제공하므로, 먼저 무료로 만져보고 결정한다.

## 처음 시작할 때의 추천 조합

이 책의 독자(비개발자)가 처음 시작한다면 다음 순서를 권한다.

### 1단계: 무료 빌더로 검증하기

Lovable이나 v0의 무료 범위 안에서 20장의 명세서를 붙여넣고 결과물을 본다. "내가 생각한 게 이 모양인가"를 확인하는 단계다. 이 단계에서는 돈을 쓰지 않는다. 명세서의 빈틈도 이 과정에서 발견된다.

### 2단계: 필요하면 유료 1개만 고르기

무료 범위가 부족해지면 그때 유료 1개를 고른다. 기준은 간단하다. 명세서 파일과 함께 차근차근 만들고 싶으면 Claude Code(Pro), 화면을 보면서 고치고 싶으면 Cursor(Pro), 계속 브라우저에서 빠르게 만들고 싶으면 쓰던 빌더의 유료를 고른다. 2개 이상을 동시에 결제할 필요는 없다.

### 3단계: 프로젝트가 커지면 옮기기

빌더형으로 시작한 프로젝트가 커져서(화면이 10개를 넘거나, 복잡한 기능이 들어가거나) 한계가 느껴지면 그때 Claude Code나 Cursor로 옮긴다. 파일을 내려받아서(빌더마다 내보내기 기능이 있다) 폴더에 넣고 이어서 작업한다.

이 순서를 지키면 "유료 결제했는데 안 쓰게 됐다"는 일을 막을 수 있다. 도구는 목적에 맞는 것을 하나씩 들이는 게 원칙이다.

## 무료로 시작하는 첫날의 순서

막상 도구를 골라도 "그래서 뭘 먼저 하냐"가 막막하다. 첫날 1시간을 이렇게 쓰면 된다.

1. 도구 하나를 고른다(위 체크리스트 참고). 가입 또는 설치까지만 한다.
2. 20장에서 쓴 명세서를 연다. 아직 안 썼으면 목적 한 문장과 화면 3개만 적는다.
3. AI에게 명세서를 붙여넣고 "1단계(메뉴판 화면)부터 만들어줘"라고 시킨다.
4. 결과물을 눈으로 확인한다. 마음에 안 드는 부분은 "여기를 이렇게 고쳐줘"라고 말한다.
5. 1단계가 완료 기준을 맞췄으면 그날은 여기까지다. 다음 날 2단계로 간다.

첫날 목표는 "화면 하나를 내 손으로 띄워보는 것"이다. 거창한 완성품이 목표가 아니다. 화면 하나가 뜨면 "아, 이렇게 되는구나" 하는 감이 잡힌다.

## 도구 선택 체크리스트

결정하기 전에 아래 질문에 답해 본다.

- 설치 없이 바로 시작하고 싶은가 → 빌더형(v0, Lovable, Replit)
- 명세서 파일을 곁에 두고 체계적으로 만들고 싶은가 → Claude Code
- 화면을 보면서 부분 수정을 자주 하고 싶은가 → Cursor
- 만든 것을 바로 인터넷에 공개하고 싶은가 → Replit(배포 기능 내장)

하나만 고르지 않아도 된다. "Lovable로 빠르게 만들고, Cursor로 다듬는다"처럼 섞어 쓰는 사람도 많다. 중요한 것은 도구가 아니라 20장의 명세서다. 명세서가 탄탄하면 어떤 도구에서도 비슷한 결과가 나온다.

다음 장(30장)부터는 Part 3이다. 도구를 골랐다면 이제 AI에게 일을 시키는 실전 대화법을 다룬다. 첫 번째는 "작은 단위로 나누어 시키기"다.

## 유료로 넘어가기 전에 확인할 것

무료 범위가 부족해 "유료로 올릴까" 고민될 때 아래를 점검한다.

- 무료 범위 안에서 화면 2~3개는 만들어봤는가. 하나도 안 만들어봤는데 유료부터 결제하는 건 순서가 바뀌었다.
- 부족한 게 사용량인가, 기능인가. 사용량이 부족하면 상위 플랜을, 기능이 부족하면 다른 도구를 고려한다.
- 한 달만 써보고 판단할 수 있는가. 대부분 월 단위 결제라 한 달 써보고 끊을 수 있다. 연간 결제는 할인율이 높지만, 3개월은 써보고 결정한다.

## 두 개를 섞어 쓰는 예

"Lovable로 빠르게 만들고, Cursor로 다듬는다"는 조합이 실제로 많이 쓰인다. 흐름은 이렇다.

1. Lovable에서 명세서를 붙여넣고 첫 버전을 만든다(무료 범위 안).
2. 결과물 파일을 내려받는다(Lovable의 내보내기 기능).
3. Cursor에서 폴더를 열고 "이 부분을 이렇게 고쳐줘"라며 다듬는다.

이렇게 하면 "빠른 시작"과 "정밀한 수정"을 둘 다 가져간다. 결제는 Cursor Pro 하나만 해도 되는 경우가 많다.

## 도구와 상관없이 통하는 것

마지막으로 강조할 점이다. 도구가 바뀌어도 통하는 것은 20~21장의 명세서와 30장의 나누기 원칙이다. 명세서가 탄탄하면 Lovable에서도, Claude Code에서도 비슷한 결과가 나온다. 반대로 명세서 없이 비싼 유료 도구를 써도 결과는 신통치 않다.

그래서 이 책의 순서는 "명세서 → 도구 → 나누기 → 디버깅 → 백업"이다. 도구는 3번째가 아니라 2번째지만, 1번째인 명세서가 먼저다. 도구를 고르는 데 시간을 쓰기 전에 명세서 한 장을 먼저 쓰는 게 순서다.
