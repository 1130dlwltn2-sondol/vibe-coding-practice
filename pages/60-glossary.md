# 60. 부록: 비개발자를 위한 용어 사전

이 책에서 나온 개발 용어를 쉬운 말로 정리했습니다. 바이브 코딩을 하다 AI나 개발자가 이 단어를 쓰면 이 페이지를 찾아보세요.

가나다 순입니다.

API (에이피아이): 프로그램끼리 약속한 대화 방식. 예를 들어 결제 기능을 가져다 쓸 때 "이 주소로 이렇게 요청하면 결과가 온다"는 약속을 API라고 합니다.

GitHub (깃허브): 코드를 저장하고 공유하는 웹사이트. 바이브 코딩으로 만든 파일을 백업하는 금고이자, 개발자에게 넘길 때 건네는 서류 봉투 역할을 합니다.

URL (유알엘): 인터넷 주소. https:// 로 시작하는 그 문자열입니다.

UI (유아이): 사용자가 눈으로 보고 손으로 만지는 화면 부분. 버튼·메뉴·입력창의 배치와 생김새입니다.

UX (유엑스): 사용자가 서비스를 쓰면서 느끼는 전체 경험. 버튼이 예뻐도(좋은 UI) 누르기 어려우면(나쁜 UX) 소용이 없습니다.

개발 환경: 코드를 만들고 실행해 보는 작업 공간. Cursor 같은 에디터나 Replit 같은 웹사이트가 이에 해당합니다.

관리 화면: 서비스 운영자가 쓰는 뒷면 화면. 주문 목록 확인, 회원 관리 같은 일을 합니다. 일반 사용자에게는 보이지 않게 둡니다.

랜딩 페이지: 방문자를 맞이하는 첫 화면 한 장. 서비스 소개와 신청 버튼이 핵심입니다.

리팩토링: 동작은 그대로 두고 코드 구조만 정리하는 작업. 방은 그대로인데 가구 배치를 바꾸는 것과 비슷합니다.

배포: 만든 서비스를 인터넷에 올려 누구나 접속할 수 있게 하는 일. "출판"에 해당합니다.

백엔드: 화면 뒤에서 데이터를 저장하고 계산하는 부분. 주문을 받아 DB에 적는 일을 합니다.

백업: 파일을 별도 장소에 복사해 두는 것. 바이브 코딩에서는 GitHub에 저장하는 것이 백업입니다.

보안: 남이 못 보게·못 건드리게 막는 일. 로그인, 접근 제한, 비밀값 분리가 대표적입니다.

빌더: 브라우저에서 말로 설명하면 앱을 만들어 주는 도구. Lovable, v0, Replit, Bolt.new가 대표적입니다.

서버: 24시간 켜져 있는 컴퓨터. 서비스의 파일과 데이터를 올려 두고 방문자의 요청에 답합니다.

에이전트: 목표를 주면 스스로 여러 단계를 수행하는 AI. Claude Code나 Cursor의 에이전트 모드처럼 파일을 읽고 고치고 실행까지 합니다.

오류 메시지: 프로그램이 "여기서 막혔다"고 뱉는 문장. 영어로 길게 나오지만, 디버깅 대화의 가장 중요한 단서입니다.

인증: "당신이 누구인지" 확인하는 절차. 로그인이 대표적입니다. 인증이 없으면 누구나 관리자 화면에 들어갈 수 있습니다.

인코딩: 글자를 컴퓨터가 저장하는 방식. 한글이 깨져 보이면 인코딩 문제인 경우가 많습니다.

자동 배포: GitHub에 파일을 올리면 호스팅이 알아서 최신 버전을 인터넷에 반영하는 방식. 수동으로 파일을 올릴 필요가 없습니다.

프런트엔드: 사용자가 보는 화면 부분. 백엔드와 짝을 이룹니다.

프롬프트: AI에게 주는 지시문. 바이브 코딩에서는 "기획서이자 설계도"입니다.

프로토타입: 아이디어를 빠르게 확인하려고 대충 만든 시제품. 완제품이 아니라 검증용입니다.

환경 변수: 코드 밖에 두고 읽어 쓰는 설정값. API 키 같은 비밀값을 코드에 직접 적지 않고 여기에 둡니다.

호스팅: 만든 서비스를 인터넷에 올려 주는 임대 공간. Vercel, Netlify, Cloudflare Pages가 대표적이며 무료로 시작할 수 있습니다.

환각: AI가 그럴듯하지만 틀린 내용을 만들어 내는 현상. 코드에서는 "돌아가는 것처럼 보이는 잘못된 로직"으로 나타납니다.

히스토리: GitHub에 저장된 변경 기록. 언제 무엇을 바꿨는지가 남아 있어 망가졌을 때 이전으로 되돌릴 수 있습니다.

API 키: 외부 서비스를 쓸 때 내 신분을 증명하는 비밀번호 같은 문자열. 절대 코드에 그대로 적거나 공개 저장소에 올리면 안 됩니다.

CSS: 화면의 생김새(색·글꼴·배치)를 정하는 규칙. HTML이 뼈대라면 CSS는 옷입니다.

DB (데이터베이스): 정보를 표 형태로 저장하는 창고. 회원 목록, 주문 내역이 여기에 쌓입니다.

HTML: 웹 화면의 뼈대. "여기에 제목, 여기에 버튼"을 정합니다.

MVP: 최소 기능 제품. 핵심 기능 하나만으로 "이게 팔리는지" 검증하는 가장 작은 버전입니다.

URL 파라미터: 주소 뒤에 붙는 추가 정보. 예: ?page=2 는 "2페이지를 보여줘"라는 뜻입니다.
